## حالة المشروع الحالية

بدأ تأسيس الخادم المركزي محليًا في backend/: تصميم البيانات والصلاحيات،
قائمة API، ومخططات التفعيل والتصريح والسياسة. نجحت 13 حالة اختبار للعقود؛
لا توجد خدمة منشورة أو قاعدة بيانات مطبقة أو تحقق تشفيري منفذ بعد.
مقعد التجربة والاشتراك الأساسي واحد لكل منهما؛ الهواتف الإضافية برسوم.
تعريف الشهر وصلاحية الدعوة والاستبدال ما زالت تحتاج حسمًا.

الملخص المحدث للمنجز والمؤجل وترتيب التنفيذ موجود في بداية
[الخطة التجارية](COMMERCIAL_EXECUTION_PLAN.md#ملخص-التنفيذ-المعتمد).

- مؤكد بتجربة المستخدم: الماوس، الكتابة اللحظية، إعادة الاتصال في بيئته،
  وفتح الكيبورد تلقائيًا بعد تحديث الهاتف والسيرفر.
- منفذ ويحتاج استكمال التحقق: ملفات الحواسيب، الأسرار المحمية، TLS وQR،
  المراقبة التكيفية، الوسائط والتشغيل التلقائي. TLS ليس افتراضيًا بعد.
- غير منفذ: الخادم المركزي والحسابات والتراخيص والدفع ولوحة الأدمن وiPhone
  والمثبت التجاري والنشر على المتجرين.
- التالي: تثبيت القواعد والعقود، إغلاق الأمان المحلي، ثم بناء الخادم المركزي
  ودمج التفعيل والمقاعد وAndroid ولوحة الأدمن. جدوى iOS والدفع تفحص مبكرًا.
- مقترح تقني قيد الاعتماد: Supabase Auth/PostgreSQL/Edge Functions مع SMTP.
  لوحة الويب للأدمن؛ لا بوابة عميل مستقلة ضمن النطاق الحالي.

## سجل مراحل التنفيذ السابقة

ما يلي سجل تاريخي. عبارات «لم يعاد تشغيل السيرفر» و«الاختبار مؤجل» تخص
وقت كل مرحلة، ولا تتجاوز ملخص الحالة المحدث أعلاه.

- مرحلة `0.43` / Android `0.36`: قائمة «حواسيبي» حتى 20 حاسوبًا، لكل منها رمز مشفّر مستقل وعنوان ومنفذ وبصمة TLS وكاش IPv6. حفظ آخر اتصال ناجح، واختيار اتصال نشط واحد، وإضافة حاسوب ونسيان محلي بتأكيد دون المساس بالبقية. الاقتران الحالي يرحّل دون تغيير رمزه. الحالة «محفوظ» لا تعني أن الحاسوب متاح الآن؛ «متصل» تخص الجلسة النشطة المتحقق منها فقط. اختبار عدة حواسيب فعلية وترقية هاتف المستخدم ما زال مؤجلًا، ولم يعاد تشغيل السيرفر.

- مرحلة `0.42`: تحديد إطار طلب TCP بـ16 KiB قبل تحليل JSON، وميزانية مشتركة عبر IPv4 وIPv6 بحد 64 اتصالًا نشطًا و16 لكل عنوان قبل إنشاء خيط أو تفاوض TLS. جدولة إطفاء الحاسوب ممنوعة عند إيقاف التحكم، وإلغاء إطفاء سابق يبقى متاحًا للهاتف الموثوق. نجحت 75 حالة Python في عمليات منفصلة. لم يعاد تشغيل سيرفر المستخدم؛ التطبيق بقي 0.35. لا تمثل هذه الحدود ضمانًا ضد إغراق الشبكة، وحدود ردود Android وتشفير الاتصال الإلزامي وموافقة الاقتران الأولي وصلاحيات الطاقة ما زالت مطلوبة.

- مرحلة `0.41` / Android `0.35`: حماية أسرار الاقتران على Windows عبر DPAPI ومجلد خاص، وعلى Android عبر Keystore وAES-GCM، مع ترحيل يحافظ على الرموز المعتمدة والمعلّقة ورفض التلف أو فقدان المفتاح دون استبدال صامت. لم يعاد تشغيل سيرفر المستخدم ولم تثبت النسخة على هاتفه. تفعيل TLS الإلزامي وحماية الاقتران الأولي وحدود موارد الطلبات وصلاحيات أوامر الطاقة ما زالت مطلوبة قبل البيع.

- مرحلة `0.40.0-secure-startup`: دمج وضع TLS مع التشغيل التلقائي عبر إعداد مستقل للتشغيل القادم، وتأكيد المستخدم والتحقق من الهوية قبل الحفظ. فشل الإعدادات أو الهوية يوقف التشغيل ولا يرجع للنقل غير المشفر أو يولّد هوية بديلة. أضيف تحميل هوية موجودة حصرا داخل السيرفر عند التشغيل التلقائي الآمن. نجحت 60 حالة Python؛ Android بقي 0.34. لم يفعل TLS ولم تعدّل إعدادات الجهاز الحالي ولم يعاد تشغيل السيرفر؛ اختبار الهاتف وإقلاع Windows المشفر مؤجل حتى عودة المستخدم.

- مرحلة `0.39` / Android `0.34`: سياسة اختيار USB network تجريبية عبر Network APIs على Android 12+، مع وضع USB فقط يرفض الرجوع لـ Wi-Fi أو بيانات الهاتف، وفحص 96 تركيبة سياسة ضمن 51 حالة Python. ليست إثباتا لعمل USB tethering؛ واجهته التابعة قد لا تظهر للتطبيق كشبكة. اختبار Samsung/Windows بالكابل مؤجل ولا تستخدم ADB أو صلاحيات root أو مقابس افتراضية لتجاوز قيود النظام. Bluetooth وUSB accessory غير منفذين بعد. راجع `USB_NETWORK.md`.

- قرار اللغات: الإنجليزية أساس المنتج وافتراضية للتثبيت الجديد، ثم لغة واجهة يختارها المستخدم. لا تحويل تلقائي للعربية ولا تغيير لغة الكيبورد؛ تحفظ الاختيارات السابقة. مرحلة `0.38` تضيف ست لغات لنافذة الحاسوب مع تبديل فوري وحفظ وفحص اكتمال النصوص. Android `0.33` يعتمد الإنجليزية افتراضيا، ويظل حاليا بترجمتين: الإنجليزية والعربية وخيار لغة النظام. تغطية لغات العالم هدف تدريجي وليس ادعاء مكتمل. راجع `LANGUAGES.md`؛ مراجعة الترجمات وRTL والخطوط بصريا مؤجلة.

- مرحلة `0.37.0-desktop-dashboard`: نافذة حاسوب أصلية لحالة السيرفر وزمن الاستجابة ونمط النقل وحالة التحكم وقائمة الأجهزة الموثوقة وآخر ظهور. تحديث خلفي كل خمس ثوان وخيار التشغيل مع Windows القابل للإلغاء. لا تشغّل أو توقف السيرفر، ولا تغيّر TLS أو بدء التشغيل بمجرد فتحها. نجحت 46 حالة Python تشمل فحص TLS والسيرفر القديم وإنشاء نافذة مخفية وإغلاقها دون تعديل النظام. المعاينة البصرية الكاملة وتعريب واجهة الحاسوب لم ينجزا بعد. لم تفتح نافذة فوق جلسة المستخدم البعيدة؛ Android بقي 0.32.

- مرحلة `0.36.0-local-qr` / Android `0.32`: ماسح QR داخل التطبيق، تحقق صارم من عنوان محلي وبصمة شهادة وتذكرة مؤقتة، وتأكيد قبل حفظ إعدادات الاتصال. السيرفر يعرض QR فقط عند تشغيله عمدا بخياري `--tls --pairing-qr`؛ صلاحية خمس دقائق وهاتف واحد مع إعادة محاولة آمنة. نجحت 39 حالة Python وبناء Android وlint. لم يفعل على السيرفر الحالي لأن المستخدم بعيد ويعتمد على اتصال قائم؛ فحص الكاميرا والواجهة والهاتف مؤجل. التفاصيل `QR_PAIRING.md`.

- مرحلة `0.35.0-pinned-tls` / Android `0.31`: ربط TLS اختياري فعليا بطبقات اتصال Android والسيرفر مع إدخال بصمة محلية موثوقة ورفض البصمة المختلفة والنقل غير المشفر. نجحت 34 حالة Python تشمل Java ضد معالج السيرفر الحقيقي. بناء Android وlint نجحا؛ اختبار الهاتف والواجهة الأصلية وترحيل التشغيل التلقائي لم ينجزا بعد. الجلسة الحالية لم تتغير. التفاصيل `PINNED_TLS.md`.

- أُنجز أساس هوية Windows المحمية بـ DPAPI وشهادة TLS مستقلة عن IP، واختبارات اتصال TLS حقيقي ورفض شهادة مختلفة. نجحت جميع حالات Python الـ33 بعد التحسين الأخير لحماية ملف التحميل المؤقت. لم توصل الوحدة بعد بمستمع الإنتاج أو Android؛ الاتصال الحالي غير مشفر، ولم يُعد تشغيل السيرفر. راجع `SECURITY.md` للحدود وخطوات التكامل.

- التشغيل مع Windows: أضيف خيار قابل للتفعيل والإلغاء لحساب المستخدم، وفُعّل على جهاز الاختبار. اختبارات التسجيل والإلغاء نجحت؛ بدء التشغيل الفعلي بعد إعادة تشغيل جديدة لم يؤكد بعد. التفاصيل في `WINDOWS_STARTUP.md`.
- حماية الاقتران: أضيف حد خمس محاولات غير موثقة لكل عنوان، ومئة محاولة إجمالا خلال نافذة ستين ثانية. الحجز ذري عبر الاتصالات المتزامنة، والذاكرة محدودة بعدد المحاولات المقبولة. تغيير اسم الجهاز لا يعيد العداد. تشمل المحاولات المقبولة بالرمز أيضا، وليس التخمين الخاطئ فقط.
- إعادة الاتصال بسر صحيح تمر قبل عدادات الاقتران، فلا يمنع تقييد إضافة الأجهزة هاتفا موثوقا من العودة. رد التقييد متوافق مع العملاء الحاليين (`unauthorized`) مع `errorCode` و`retryAfterSeconds`؛ عرض العد التنازلي في Android لم ينفذ بعد.
- نجحت 26 حالة اختبار Python، بما فيها اختبارات النقل ولوحة المفاتيح والتشغيل التلقائي والحدود المتزامنة. لم يُعد تشغيل السيرفر العامل لتطبيق هذا التغيير أثناء جلسة المستخدم؛ يسري عند تشغيله القادم.
- حدود الحماية: العدادات مؤقتة وتصفّر عند إعادة تشغيل السيرفر. يمكن لمصدر عدائي استهلاك ميزانية الاقتران الجديدة؛ الهواتف الموثوقة لا تتأثر بهذا العداد. هذه ليست حماية شاملة من إغراق الشبكة، وليست بديلا عن TLS ورمز مؤقت وموافقة الحاسوب.
- التالي بالترتيب: هوية حاسوب دائمة واتصال مشفر مع تحقق من الهوية، ثم اقتران أولي مؤقت وموافقة محلية، ثم اكتشاف أولي متعدد الحواسيب وواجهة حاسوب ومثبت مستقل. لا تحكم عبر الإنترنت ولا تعديل تلقائي لمسارات الشبكة.
- يبقى الرمز التجريبي `111111` بطلب المستخدم؛ لا تُطرح النسخة للبيع بهذه الإعدادات.

مرجع تصميم الحد من التخمين ومخاطر قفل المستخدمين: [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html).

## مسار IPv6 المحلي - Android 0.30

- أكد المستخدم أن Android 0.29 يعمل بشكل جيد على هاتفه.
- فحص مباشر من الحاسوب إلى عنوان IPv6 المحلي للهاتف نجح بردين دون فقدان، بمتوسط 26 مللي ثانية. لا يعد ذلك بعد اختبارا للتحكم عبر IPv6 من الهاتف.
- أضيف استقبال على عناوين IPv6 المحلية ذات النطاق المحدد فقط، مع تحديث المستمعين عند تغيّر الواجهات، ومشاركة نفس الاقتران وحالة التحكم مع IPv4.
- يحفظ Android عناوين الحاسوب المحلية بعد اتصال ناجح ويختبرها عند إعادة الاتصال، مع إثبات سر الاقتران وتعيين نطاق واجهة الهاتف. يرجع إلى IPv4 عند تعذر IPv6.
- يتطلب تمهيدا باتصال ناجح واحد لحفظ العناوين. الاكتشاف الأولي عبر IPv6 وmDNS لم ينفذ بعد؛ إذا تغيّر عنوان الحاسوب أيضا ولم ينجح IPv4، قد يلزم اكتشاف جديد.
- تأكد التحكم من Samsung عبر IPv6 بالسجل وتأكيد المستخدم. أزيل مسار Windows الخاص من المخزن الفعّال والدائم، ثم أكد المستخدم استمرار العمل بعد إعادة فتح التطبيق، وبعد قطع Wi-Fi وإعادتها وإعادة فتح التطبيق أيضا. تغيّر عنوان IPv4 فعليا وإعادة تشغيل الحاسوب لم يختبرا بعد؛ لا نساوي قطع Wi-Fi بتغيّر العنوان.

## قرار المنتج التجاري - 2026-10-07

### تنفيذ الاتصال المحلي 0.33 / Android 0.29

- نُفذت مراقبة تغيّر الشبكة، وإلغاء الجلسة والمدخلات القديمة، واستعادة محدودة في الواجهة الأمامية؛ لا يعاد إرسال أمر إدخال غامض النتيجة.
- أضيف فحص هوية خفيف كل خمس ثوانٍ أثناء ظهور التطبيق فقط، لاكتشاف توقف السيرفر أو فقدان إشعار الشبكة دون إرسال مدخلات.
- نُفذ ربط المقابس بـ Wi-Fi أو Ethernet المحلية، حتى دون إنترنت؛ لا يستخدم التحكم بيانات الهاتف أو وجهة IP عامة، ولا يتجاوز VPN نشطا افتراضيا.
- نُفذ اكتشاف موثوق بإثبات HMAC لسر الاقتران وتحدٍ جديد، وتحقق TCP قبل إعادة إرسال السر للحاسوب. يتطلب السيرفر المحدث. هذا لا يغني عن TLS أو تأمين الاقتران الأولي.
- البحث يعتمد قناع الشبكة الفعلي وعنوان مصدر رد UDP؛ الفحص البديل محدود لنافذة /24 داخل النطاق الحقيقي. دعم mDNS/NSD واختيار عدة حواسيب ما زال مؤجلا.
- الخطة المحلية فقط: الموقع للدعم والتنزيل والتحديثات، ولا خدمة وسيطة أو تحكم عبر الإنترنت. البدائل المستقبلية USB وBluetooth محلية أيضا.
- تغيّر عنوان الهاتف داخل شبكة سليمة لا يحتاج اقترانا جديدا. الشبكة الحالية ذات مسار الرد غير السليم ما زالت تحتاج تصحيح إعداداتها؛ لا ندّعي أن هذه التعديلات تغني عن مسار Windows الخاص في تلك الشبكة.

الهدف المعتمد الآن منتج قابل للنشر والبيع، لا نسخة تعمل على شبكة المطور فقط. تظل النسخة الحالية تجريبية إلى اجتياز شروط الإصدار أدناه. لا يمكن ضمان تجاوز عزل الأجهزة أو حظر الشبكة من داخل التطبيق وحده؛ يجب عرض سبب قابل للفهم وتوفير بديل مدعوم.

### نتيجة تجربة الهاتف الفعلي

- أكد المستخدم نجاح الاتصال والماوس والكتابة العربية اللحظية، ثم نجاح إعادة الاتصال بعد إغلاق التطبيق وفتحه.
- أظهر التقاط الحزم اختلاف مسار الوصول والرد بين الهاتف والحاسوب؛ نجح الاتصال بعد إضافة مسار مباشر لعنوان الهاتف `10.10.11.9/32`.
- حُفظ المسار في Windows، لكنه مرتبط بالعنوان الحالي. لم يُختبر بعد إعادة تشغيل الحاسوب، ولا يُعد إصلاحا عاما أو جزءا من مثبت المنتج.
- لا نوزع عنوان الهاتف أو إعداداته أو رمزه الثابت `111111` أو بيانات الثقة أو سجلاته ضمن إصدار العملاء.

### مراحل التنفيذ وشروط القبول

1. اتصال محلي متين: هوية ثابتة للحاسوب مستقلة عن IP، وإعادة اكتشاف الحاسوب الموثوق بعد تغير العنوان، وإلغاء الطلبات القديمة عند تغير شبكة Android. لا يُنقل رمز الثقة إلى جهاز اعتمادا على الاسم أو العنوان وحدهما.
2. استعادة الجلسة: محاولات محدودة بتأخير متدرج وتفاوت عشوائي، وإلغاء المحاولات عند الفصل اليدوي. لا تعاد أوامر الكتابة والنقر تلقائيا عند غموض نتيجة التنفيذ. لا تكرر المدخلات ولا تتراكم أثناء الانقطاع.
3. تشخيص واضح: التمييز بين فشل الوصول، وانتهاء انتظار الرد، ورفض الاقتران، وفقدان الثقة، وإيقاف التحكم. لا يُتهم جدار الحماية دون دليل. فحص الشبكة وإصلاحها لا يجريان بصلاحيات المسؤول تلقائيا.
4. أمان قبل البيع: نقل مشفر بمصادقة هوية الحاسوب أثناء الاقتران، وأسرار محفوظة بوسائل النظام، ورمز اقتران عشوائي محدود الصلاحية والمحاولات، وإبطال الأجهزة الموثوقة. مراجعة أمنية للبروتوكول قبل ادعاء أن الاتصال آمن تجاريا.
5. بدائل الاتصال: تقييم USB وBluetooth كنطاق منفصل؛ لا يظهر خيار غير منفذ للمستخدم. الشبكات المعزولة تحتاج وسيلة محلية بديلة أو تصحيح إعداداتها، لا تغييرا صامتا في مسارات Windows. التحكم عبر الإنترنت والخدمة الوسيطة مستبعدان بقرار المستخدم؛ موقع الويب للدعم والتنزيل والتحديثات فقط.
6. التوزيع: APK إصدار موقّع، ومثبت Windows مع إلغاء تثبيت نظيف، وقواعد حماية محلية محدودة ومصرح بها، وتحديثات متوافقة مع البروتوكول. بناء واجهة Android وحده لا يعيد تشغيل سيرفر المستخدم.
7. بوابة الإصدار: اختبار فعلي لشبكة عادية، وتغير IP، وتبديل Wi-Fi، ووجود VPN أو عدة بطاقات، وعزل الضيوف، وحظر المنفذ، وإعادة تشغيل السيرفر والحاسوب، وسكون الهاتف، وتزامن عملاء، وعدم تطابق نسخ البروتوكول. يسجل كل اختبار نتيجته ودليله ولا يعد ناجحا بمجرد نجاح المحاكي.

الأولوية التنفيذية: إكمال هوية الحاسوب واكتشافه واستعادة الجلسة محليا، بالتوازي مع تصميم بروتوكول الاتصال المشفر. تحسين الشكل مستمر لكنه لا يسبق شروط الاعتمادية والأمان للإصدار التجاري.

## الرؤية

`Qareeb Control` هو الاسم المعتمد للمنتج. الفكرة الأساسية: الهاتف يصبح امتدادا قريبا للحاسوب عبر Wi-Fi المحلي، مع ماوس، كيبورد لحظي، ريموت ميديا، ريموت عروض، ومركز اختصارات. النسخة الأولى تركز على Windows وAndroid.

## الحالة الحالية

تم إنجاز مرحلة التأسيس والاتصال والتحكم العملي الأول:

- هيكل المشروع موجود.
- الوثائق الأساسية موجودة.
- موقع الدعم المحلي موجود.
- سكربت إنتاج ZIP موجود.
- Desktop Server يدعم `ping`, `status`, و`hello`.
- الأجهزة الموثوقة تحفظ محليا في `desktop-server/data/trusted-devices.json`.
- عميل الاختبار المحلي يدعم الاقتران وأوامر الماوس.
- أوامر `mouse_move`, `mouse_click`, `scroll`, و`control_stop` موجودة ومحمية بالـ token.
- أوامر `key_press`, `type_text`, `media_control`, و`shortcut` موجودة ومحمية بالـ token.
- أوامر الماوس والكيبورد لها حدود أمان، ويمكن اختبارها عبر `--dry-run-controls` بدون تحريك المؤشر أو الكتابة الفعلية.
- النصوص القصيرة محدودة بطول 160 حرفا ولا يتم تسجيلها في logs.
- تطبيق Android أولي موجود داخل `mobile-app/` مع واجهة اتصال واقتران وتراكباد وكيبورد وميديا وإدارة أساسية.
- تطبيق Android يستطيع اكتشاف السيرفر تلقائيا داخل الشبكة عبر زر `بحث`، مع fallback TCP scan عند فشل UDP broadcast.
- تطبيق Android يتعرف على Android Emulator، يملأ `10.0.2.2` تلقائيا، ويملك زر اختبار سريع.
- الكيبورد المباشر في Android موجود داخل واجهة تحكم مقسمة: تراكباد للماوس ولوحة مفاتيح أزرار، مع مستقبل مخفي لكيبورد الهاتف.
- واجهة Android تخفي قيمة `token` عند عرض استجابة الاقتران.
- تم صقل التراكباد: منع ScrollView من خطف السحب، ودعم تمرير بإصبعين، وإعدادات سريعة للحساسية.
- إدارة الأجهزة الموثوقة موجودة في السيرفر: عرض، حذف، تغيير رمز الاقتران، وإعادة تفعيل التحكم.
- إعدادات محلية موجودة في السيرفر: حساسية الماوس، حساسية التمرير، وحد النص.
- أوامر الطاقة الأساسية موجودة: إطفاء الحاسوب بتأكيد صريح، وإلغاء الإطفاء المجدول.
- الهاتف الفعلي استطاع الاتصال بالسيرفر، وتجربة الماوس نجحت.
- رمز الاقتران الافتراضي للتجربة الحالية مثبت على `111111`.
- المشكلة المفتوحة الآن: ضغط أزرار الأحرف من الهاتف يصل للسيرفر لكن لا يظهر دائما في مربع النص المحدد على Windows، لذلك يجب إغلاق مسار الكيبورد اللحظي قبل اعتبار النسخة مستقرة.

لم يتم بعد:

- تأكيد الكيبورد اللحظي على هاتف فعلي بعد تعديل مسار الأحرف إلى `key_press`.
- اختبار إدخال العربية والرموز من كيبورد الهاتف المخفي بعد إصلاح الإدخال الأساسي.
- تحسين واجهة الهاتف بعد تجربة الجهاز الفعلي الطويلة.
- إضافة واجهة سطح مكتب رسومية لاحقا إن احتجناها.

## بروتوكول الرسائل

كل رسالة JSON في سطر واحد وتنتهي بـ newline.

قواعد عامة:

- كل رسالة يجب أن تحتوي `type`.
- كل أمر تحكم يجب أن يحتوي `deviceId` و`token` صالحين.
- كل رسالة لها رد واضح: نجاح أو خطأ.
- الرسائل غير المعروفة لا توقف السيرفر، بل تعيد `error`.
- يتم وضع حدود للقيم الرقمية والنصية قبل تنفيذ أي أمر على النظام.

رسائل أساسية:

- `ping`: اختبار الاتصال.
- `hello`: بدء الاتصال أو إعادة الاتصال.
- `status`: حالة السيرفر.
- `mouse_move`: حركة المؤشر.
- `mouse_click`: نقر يمين أو يسار أو وسط.
- `scroll`: تمرير.
- `control_stop`: إيقاف التحكم من جهاز موثوق.
- `key_press`: مفاتيح محددة ومسموحة.
- `type_text`: كتابة نص قصير بحد طول واضح.
- `media_control`: صوت وتشغيل وإيقاف.
- `shortcut`: اختصارات محددة مسبقا.
- `error`: رد خطأ واضح.

أمثلة:

```json
{"type":"ping"}
```

```json
{"type":"mouse_move","deviceId":"phone-1","token":"...","dx":12,"dy":-4}
```

```json
{"type":"error","reason":"unauthorized"}
```

## الأمان

هدف الأمان: الحاسوب لا يقبل التحكم إلا من هاتف تم السماح له صراحة.

طبقات الأمان:

1. رمز اقتران يظهر على الحاسوب.
2. Token خاص بكل جهاز موثوق.
3. قائمة أجهزة موثوقة محفوظة محليا.
4. أمر إيقاف فوري للتحكم.
5. أوامر حساسة معطلة افتراضيا.
6. سجل محلي لمحاولات الاتصال والأخطاء.
7. رفض أي أمر تحكم قبل التحقق من الجهاز.
8. حدود أمان لحركة الماوس والتمرير والنقر.

السياسات:

- لا يتم تسجيل النصوص المكتوبة بالكامل في log.
- `shutdown_computer` موجود لكنه يحتاج token وتأكيد صريح ومهلة إلغاء؛ أما Sleep وRestart فتبقى مؤجلة.
- Clipboard وFile manager وCustom commands مؤجلة لما بعد MVP.
- يمكن حذف جهاز موثوق من السيرفر لاحقا.
- يمكن تغيير رمز الاقتران لاحقا.

## التخزين المحلي

ملفات التشغيل داخل `desktop-server/data/`:

- `trusted-devices.json`: الأجهزة الموثوقة والـ tokens.
- `events.log`: سجل أخطاء واتصالات بدون بيانات حساسة.

ملفات تشغيل إضافية:

- `settings.json`: الحساسية وحد النص والإعدادات المحلية الآمنة.

على Android:

- حفظ آخر IP و Port.
- حفظ token للجهاز الموثوق.
- حفظ إعدادات الحساسية محليا.

- إعدادات حساسية التمرير وحد النص.
- تحسين رسائل الخطأ.
- اختبار انقطاع الشبكة وإعادة الاتصال.
- مراجعة البروتوكول قبل التوزيع.

الناتج المقبول:

- يستطيع المستخدم إدارة الأجهزة الموثوقة.
- يمكن حل مشاكل الاتصال الأساسية من الرسائل الظاهرة.
- لا توجد أوامر حساسة مفعلة بدون موافقة واضحة.

الحالة: إدارة الأجهزة والإعدادات الأساسية منجزة عبر أوامر السيرفر وعميل الاختبار وتطبيق Android الأولي. بقي الصقل وتجربة الهاتف.

### مرحلة الإغلاق الحالية: كيبورد وتجربة هاتف

المهام:

- إرسال أزرار الأحرف والأرقام في Android كأوامر `key_press` مباشرة.
- إبقاء `type_text` للكتابة العربية والرموز والنصوص القادمة من كيبورد الهاتف.
- إضافة fallback في Windows يحاول ضغط المفتاح الفعلي للحرف قبل مسار Unicode.
- بناء APK جديد وتحديث `releases/phone-pc-remote-android-debug.apk`.
- إعادة تشغيل السيرفر واختبار حرف داخل Notepad أو أي مربع نص محدد.

الناتج المقبول:

- عند الضغط على حرف في الهاتف يظهر فورا في مربع النص المحدد على الحاسوب.
- Space وEnter وBackspace تعمل كضغطات مفاتيح.
- لا تظهر أخطاء `text_input_failed` عند استخدام أزرار الحروف الإنجليزية والأرقام.

### الأسبوع 8: التجهيز والتسليم

المهام:

- تحسين واجهة الهاتف.
- اختبار Windows 10 و Windows 11.
- تجهيز APK.
- تجهيز Windows package أو طريقة تشغيل واضحة.
- تحديث موقع الدعم.
- كتابة خطوات تشغيل مختصرة للمستخدم النهائي.
- اختبار النقل على مجلد جديد بعد فك الضغط.
- إنتاج `phone-pc-remote-latest.zip`.

الناتج المقبول:

- نسخة MVP قابلة للتجربة محليا.
- المستخدم يستطيع تشغيل السيرفر والتطبيق بدون شرح طويل.
- ZIP يحتوي كل ما يلزم لاستكمال العمل أو النقل.

## خطة الاختبار

اختبارات السيرفر:

- تشغيل السيرفر بدون أخطاء.
- `ping` يرجع `pong`.
- `status` يرجع حالة السيرفر والتحكم.
- JSON غير صالح يرجع `invalid_json`.
- رسالة غير معروفة ترجع `unsupported_message`.
- اقتران صحيح يصدر token.
- اقتران خاطئ يرفض الاتصال.
- token صحيح يسمح بالأوامر.
- token خاطئ يرفض الأوامر.

اختبارات التحكم:

- حركة ماوس صغيرة.
- حركة ماوس كبيرة يتم تحديدها للحد الآمن.
- نقر يمين ويسار ووسط.
- تمرير.
- إيقاف فوري.
- رفض التحكم بعد الإيقاف.
- اختبار dry-run بدون تحريك المؤشر الحقيقي.

اختبارات Android لاحقا:

- حفظ IP و Port.
- حفظ token.
- إعادة الاتصال.
- عرض حالة الاتصال.
- اكتشاف السيرفر عبر UDP ثم TCP scan عند الحاجة.
- إرسال أوامر تراكباد بدون تأخير مزعج.
- ظهور الأحرف مباشرة في الحقل المحدد على Windows.

اختبارات التسليم:

- تشغيل المشروع بعد فك ZIP في مجلد جديد.
- فتح موقع الدعم المحلي.
- تشغيل السيرفر من التعليمات.
- التأكد أن `releases/` وملفات التشغيل الحساسة لا تدخل داخل ZIP الناتج.

## معايير الجاهزية للـ MVP

النسخة تعتبر جاهزة عندما يتحقق التالي:

- تطبيق Android مبني ومثبت باسم `Qareeb Control` ويتحكم بماوس Windows داخل الشبكة المحلية.
- الاقتران يعمل ولا يحتاج تكرارا في كل مرة.
- الكيبورد الأساسي والميديا يعملان.
- الأجهزة غير الموثوقة لا تستطيع التحكم.
- المستخدم يستطيع إيقاف التحكم بسرعة.
- يوجد ZIP محدث وموقع دعم وتعليمات تشغيل.
- لا توجد حاجة لأي خدمة إنترنت أثناء التشغيل.

## المخاطر والتعامل معها

- أدوات Android المحلية مثبتة الآن: JDK 17 وAndroid Studio وSDK محلي وGradle محلي. تم إنتاج APK تجريبي واختباره على Android Emulator بنجاح، مع تحسينات اتصال المحاكي وإخفاء token في الواجهة. بقي اختبار الهاتف الفعلي وتحسين تجربة اللمس على جهاز حقيقي.
- التحكم في Windows قد يتطلب أذونات في بعض البيئات: نبدأ بـ `ctypes` المحلي ونوثق أي قيود تظهر.
- الشبكة المحلية تمنع الاتصال: نضيف تعليمات Firewall وIP في موقع الدعم.
- الأوامر الحساسة خطرة: إطفاء الحاسوب أصبح محميا باقتران وtoken وتأكيد صريح ومهلة إلغاء؛ باقي الأوامر الحساسة تبقى مؤجلة.
- تأخير اللمس مزعج: تم تحسين منع تداخل التراكباد مع ScrollView وإضافة تمرير بإصبعين؛ بقي اختبار الإحساس على هاتف حقيقي.
