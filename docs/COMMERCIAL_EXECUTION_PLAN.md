# خطة تنفيذ Qareeb Control التجارية

تاريخ الاعتماد المرجعي: 2026-10-08.
الحالة: خطة تنفيذ، وليست إعلانًا باكتمال المزايا أو الجاهزية للبيع.
هذه الوثيقة مرجع النطاق التجاري الحالي عند تعارضه مع الخطط التاريخية.

## ملخص التنفيذ المعتمد

آخر ترتيب: 2026-10-08. الإصدار 0.47 / Android 0.40.
«منفذ» لا تعني «جاهز للبيع». موافقة المستخدم على خطة ليست تنفيذًا لها.

### أ. منجز ومؤكد بتجربة المستخدم

- تطبيق Android وبرنامج تحكم Windows يعملان عبر الشبكة المحلية.
- تحريك الماوس والكتابة اللحظية بالعربية دون زر إرسال نص.
- إعادة الاتصال بعد إغلاق التطبيق وتعطيل/إعادة Wi-Fi وإعادة تشغيل الجهاز،
  في بيئة المستخدم المختبرة؛ ليست ضمانًا لجميع الشبكات.
- فتح كيبورد الهاتف تلقائيًا عند تحديد حقل كتابة يدعمه كشف Windows،
  بعد تثبيت Android 0.37 وتحديث السيرفر.

### ب. منفذ برمجيًا ويحتاج تحققًا تجاريًا إضافيًا

| الجزء | دليل التنفيذ | ما بقي للتحقق |
| --- | --- | --- |
| حواسيبي وملفات الاقتران المستقلة | اختبارات آلية ومحاكي، حد تقني 20 | عدة حواسيب فعلية وترقيات دون فقد أسرار |
| حفظ الأسرار | Keystore/AES-GCM وDPAPI مع اختبارات | فحص ترحيل الإنتاج والنسخ والترقية |
| TLS مثبت الهوية وQR | دعم واختبارات موجودة | جعلهما مسار الإطلاق الآمن والتحقق من الهاتف |
| تحسين الاتصال الاختياري | اختبار سياسة وTCP ومحاكاة طابور | اختبار طابور Android والتذبذب والفقد فعليًا |
| كشف حقل الكتابة | تجربة المستخدم واختبارات | مصفوفة متصفحات ومحررات وحقول مخصصة |
| الوسائط والاختصارات والطاقة | أوامر وواجهات موجودة | انحدار وظيفي وصلاحيات وأوامر خطرة |
| نافذة Windows والتشغيل التلقائي | تنفيذ سابق واختبارات | تثبيت نظيف وترقية وتشغيل آمن ومراجعة بصرية |
| اللغات | Android إنجليزي/عربي؛ Windows ست لغات | مراجعة النصوص وRTL وتوسيع تدريجي |
| USB network | سياسة اختيار تجريبية | إثبات العمل بالكابل على أجهزة فعلية |

تنبيه: آخر تشغيل معروف للسيرفر دون --tls وبرمز اختبار 111111؛ هذا ليس
إعدادًا تجاريًا معتمدًا. لا نغيره أثناء جلسة المستخدم دون تنسيق.

### ج. مخطط له وغير منفذ

- الخادم المركزي وقاعدة بيانات الحسابات والاشتراكات.
- التسجيل وتوثيق البريد والاستعادة والبصمة الاختيارية.
- محرك التصاريح والتحقق اليومي وفترة السماح وفرض الحد الأدنى للإصدار.
- الحساب الرئيسي والأعضاء والدعوات والمقاعد المدفوعة.
- لوحة ويب للأدمن فقط؛ إدارة العميل الأساسية داخل التطبيق.
- دمج مشتريات Google Play وApp Store واستعادتها ومعالجة تجديدها واستردادها.
- تطبيق iPhone، مثبت Windows التجاري، وموقع الدعم ومواد النشر.
- النشر العام وخدمة الدعم والتشغيل الإنتاجي والمراقبة والنسخ الاحتياطية.

هذا ترتيب الاعتماد، لا اشتراط إكمال كل بند قبل استكشاف الآخر. يجرى نموذج
جدوى iPhone ومنتجات الدفع مبكرًا في الحزمة 1، قبل تثبيت تصميم قد يرفضه
المتجر. لا يبدأ البيع قبل اجتياز الحزم اللازمة على المنصتين.

### هـ. قرارات تقنية مقترحة وليست معتمدة نهائيًا

- البدء بنموذج Supabase Auth وPostgreSQL وEdge Functions لخادم التفعيل،
  مع SMTP خارجي. حساب Supabase موجود لدى المستخدم؛ لم يربط بالمشروع.
- اختبار ملاءمة توقيع الترخيص والتحقق من مشتريات المتاجر قبل اعتماد المنصة.
- استضافة لوحة الأدمن وموقع الدعم قرار مستقل. Vercel موجود لدى المستخدم،
  لكنه ليس إلزاميًا لخادم التفعيل. لا نعتمد Hobby لاستخدام تجاري.
- لا حاجة مقررة الآن إلى VPS أو خدمة realtime أو نقل تحكم عبر السحابة.
- لا إنشاء خدمات أو إنفاق أو نشر إنتاجي في إطار تحديث هذه الخطة.

### و. نطاق لوحة الأدمن

- إدارة قواعد الباقات والمقاعد والتجربة والدعوات والاستبدال من سياسات خادمية
  ذات إصدارات، لا أرقام ثابتة داخل التطبيق. مسار مسودة/تحقق/معاينة/نشر مع
  صلاحيات قوية وتاريخ سريان وسجل تدقيق وحماية حقوق الاشتراكات القائمة.
- إعداد عروض البيع وربط منتجات المتجر؛ تغيير السعر يتطلب توافق إعدادات
  المتجر وموافقات الشراء، ولا يكفي تعديل رقم داخل اللوحة لتحصيل مبلغ جديد.

- ملخص الحسابات والتجارب والاشتراكات والتفعيلات وحالة الخدمات.
- إدارة المالك والأعضاء والدعوات والهواتف والمقاعد والإصدارات المدعومة.
- متابعة أدلة الدفع وحالاتها دون اختلاق شراء أو تعديل سجل المتجر.
- استثناءات دعم محددة المدة والسبب، مع سجل تدقيق لكل إجراء حساس.
- صلاحيات مالك مشروع ودعم منفصلة ومصادقة متعددة العوامل مفروضة خادميًا.
- لا كلمات مرور أو مفاتيح توقيع/اقتران أو محتوى كتابة، ولا تحكم بحاسوب عميل.

### ز. الخطوة المباشرة

بدأ تأسيس العقود داخل backend/: مخطط بيانات وصلاحيات وعمليات ذرية،
قائمة API، ومخططات طلب التفعيل والتصريح والسياسة. هذه ملفات تصميم واختبار
محلي، وليست خدمة منشورة أو قاعدة بيانات مطبقة. مقعد التجربة واحد وفق الرد
الأخير؛ الاشتراك المدفوع الأساسي كذلك بمقعد واحد، وكل هاتف إضافي برسوم.
مدة الشهر الدقيقة وصلاحية
الدعوة غير محسومتين، ولا تعتمد قيم 30 يومًا/48 ساعة افتراضيًا.

تثبيت تعريف الشهر وحدود المقاعد والاستبدال والدعوة، ثم تصميم مخطط
البيانات وAPI والتصريح. بعد ذلك نموذج خادم تجريبي: بريد موثق + تفعيل
هاتف + حجز مقعد + تصريح يتحقق منه Android وWindows، دون دفع حقيقي.
إغلاق الأمان المحلي شرط قبل ربط التراخيص بنسخة قابلة للبيع.

## 1. الهدف وحدود المنتج

تحويل الهاتف إلى ريموت محلي متقن للحاسوب: ماوس، كيبورد لحظي، وسائط
واختصارات، مع حساب موثق واشتراك مفهوم وآمن.

- النشر المستهدف: Google Play وApp Store.
- الحاسوب المستهدف للإطلاق: Windows. دعم macOS وLinux مرحلة لاحقة.
- التطبيق الحالي Android أصلي؛ نسخة iPhone لم تنفذ بعد.
- أوامر التحكم ومحتوى الكتابة لا تمر عبر خادمنا أو الإنترنت.
- الإنترنت للحساب والتوثيق والدفع والتفعيل والتحقق الدوري فقط.
- التلفازات، التحكم عبر الإنترنت، عرض الشاشة ونقل الملفات خارج نطاق الإطلاق.
- Bluetooth وUSB المضمون ليسا شرط إطلاق؛ USB network الحالي تجريبي.
- الإنجليزية لغة الأساس، العربية مدعومة، والتوسع اللغوي تدريجي ومراجع.

## 2. القرارات التجارية المعتمدة

- تسجيل الدخول وتوثيق البريد إلزاميان قبل الاستخدام.
- إنشاء الحساب وتوثيق البريد واستعادة الدخول داخل التطبيق.
- جميع مزايا Pro متاحة في تجربة شهر، وليست باقة مجانية دائمة.
- تبدأ التجربة بعد توثيق البريد وأول تفعيل ناجح؛ لا تمددها إعادة التثبيت.
- الاشتراك الأساسي يشمل هاتفًا واحدًا؛ كل هاتف إضافي يحتاج مقعدًا مدفوعًا.
- الحساب الرئيسي يدير الاشتراك والدعوات والمقاعد والفوترة.
- يستطيع المالك شراء مقاعد إضافية له أو دعوة حساب مستقل ببريد موثق مختلف
  لاستخدام مقعد متاح. الدعوة لا تزيد السعة المجانية؛ سياسة تخصيص المقعد
  الوحيد للمدعو دون هاتف للمالك تحتاج تحديدًا ضمن قواعد الدعوات.
- كل هاتف مفعّل يستهلك مقعدًا؛ قبول دعوة لا ينشئ اشتراكًا أو تجربة جديدة.
- البصمة اختيارية لفتح التطبيق؛ ليست بديلًا عن التوثيق أو الترخيص.
- خادمنا مرجع الاستحقاق؛ الهاتف والحاسوب يتحققان من تصاريح موقعة.
- محاولة تحقق يومية أثناء الاستخدام؛ سماح دون إنترنت حتى سبعة أيام من آخر
  تحقق ناجح، دون تجاوز نهاية الاستحقاق أو التجربة.
- تحديث عادي اختياري؛ حد أدنى إلزامي فقط للأمان أو التوافق مع إعلان واضح.
- انتهاء الاشتراك لا يحذف الحساب أو الاقترانات أو الإعدادات.

## 3. القرارات التي يجب حسمها قبل بناء الفوترة

1. تعريف الشهر: شهر تقويمي أم عدد أيام ثابت، وتوقيت الانتهاء المرجعي UTC.
2. أسعار الباقة والمقاعد، العملات، شهري/سنوي، والأسواق الأولى.
3. حد أقصى تجاري للمقاعد؛ لا نفترض بيع عدد مفتوح بأي آلية دفع.
4. عدد الحواسيب: اقتراح الإطلاق 20 محفوظًا، لا قرار نهائي بعد.
5. التجربة: مقعد واحد؛ سياسة الإضافات أثناء التجربة تحتاج حسمًا.
6. استبدال الهاتف، مدة الانتظار، وفك المقعد المفقود دون فتح باب المشاركة.
7. مدة الدعوة وحجز المقعد: اقتراح 48 ساعة، يحتاج اعتمادًا.
8. سياسة الإلغاء والتخفيض والاسترداد والتعثر المالي وفق قناة الشراء.
9. الشراء عبر المنصتين، نقل ملكية الاشتراك، والعضوية في أكثر من اشتراك.
10. طريقة وتوقيت قفل جلسة قائمة عند انتهاء التصريح، مع تحذير مسبق ومسار آمن.

لا نفترض أن كل متجر يسمح باشتراك جهاز إضافي متغير الكمية أو احتساب نسبي
موحد. نعتمد تصميم المنتجات بعد نموذج تجريبي في بيئتي الدفع الرسميتين.

## 4. الوضع الحالي

- الإصدار المرجعي 0.44، Android 0.37: تحكم محلي، كيبورد لحظي، ملفات
  حواسيب مستقلة، وإعادة اتصال؛ المستخدم أكد نجاح الاستخدام وإعادة الفتح.
- فتح الكيبورد عند تحديد حقل Windows يعمل بحسب تجربة المستخدم. اكتشاف
  الحقول المخصصة يعتمد على دعم الوصول؛ الزر اليدوي يبقى متاحًا.
- تحسين الاتصال التكيفي اختياري ومغلق افتراضيًا. الاختبارات المعزولة تثبت
  سلوك السياسة وتقليل إرساليات في محاكاة، لا ضمان زيادة سرعة الشبكة.
- توجد حماية محلية للأسرار ودعم TLS اختياري وQR، لكنها لا تعني اكتمال
  وضع الأمان التجاري. السيرفر الحالي شغّل دون --tls؛ يلزم انتقال آمن.
- الحسابات والتراخيص والدفع والمقاعد وخدمة الدعم وiOS غير منفذة.
- نجاح اختبارات سابقة لا يغني عن إعادة الانحدار الشاملة للنسخة المرشحة.

## 5. المعمارية

### خادم الحسابات والتفعيل

يدير المستخدمين، توثيق البريد والجلسات، العضويات، الدعوات، التفعيلات،
المقاعد، استحقاقات المتاجر، السياسات والإصدارات والتصاريح الموقعة.
لا يخزن مفاتيح الاقتران المحلية ولا يستقبل محتوى الكتابة أو التحكم.

### تطبيق الهاتف

يعرض التسجيل والاشتراك والأجهزة، يحتفظ بجلسة الحساب ومفتاح جهاز محمي،
ويجلب تصريحًا موقّعًا. ينفذ الاقتران والتحكم مباشرة على الشبكة المحلية.
تغيير الحساب لا يكشف اقترانات مستخدم آخر؛ نصمم العزل والمسح المحلي صراحة.

### برنامج Windows

يعرض حالة السيرفر وموافقات الاقتران والأجهزة، ويتحقق من التصريح ومفتاح
الهاتف وصلاحيات الجلسة قبل قبول الأوامر. لا يحتاج تسجيل حساب مستقلًا
للإطلاق، ويمكنه التحقق محليًا دون اتصال إنترنت مستقل.

### فصل الثقة

الترخيص لا يمنح الاقتران، والاقتران لا يمنح اشتراكًا. امتلاك حساب المالك
لا يتيح التحكم بحواسيب العضو. لا تعتمد حماية المزايا على إخفاء زر فقط.
إيقاف التحكم المحلي ومسارات الأمان لا تحجب بسبب انتهاء الترخيص.

## 6. تصميم الترخيص والمقاعد

- مفتاح التوقيع الخاص في إدارة أسرار خادمية، لا داخل الهاتف أو Windows.
- تصريح محدود المدة يتضمن معرف الإصدار والجهة المصدرة والجمهور، معرف
  التصريح، مفتاح الهاتف، الاستحقاق والمزايا، وقت الإصدار والانتهاء ومعرف
  مفتاح التوقيع. نقل أقل قدر لازم من بيانات الحساب للحاسوب.
- تحقق صارم من الخوارزمية والتوقيع والحقول والوقت والجمهور؛ خطة تدوير
  مفاتيح وإبطالها وتوافق الإصدارات قبل الإطلاق.
- إثبات امتلاك مفتاح الهاتف بتحدٍّ جديد وربطه بالجلسة المحلية؛ نسخ التصريح
  وحده لا يكفي. TLS مثبت الهوية لا يستبدل إثبات الترخيص والعكس صحيح.
- حجز المقعد وتفعيله ذريان؛ طلب مكرر لا يستهلك مقعدين.
- الدعوة مرتبطة بالبريد المتحقق منه، محدودة الوقت، قابلة للإلغاء، ومرة واحدة.
- إزالة الهاتف تمنع تجديد تصريحه؛ قد يستمر التصريح دون إنترنت حتى انتهائه.
  الحد ليس ضمانًا لعدد جلسات لحظي صارم أثناء السماح بالعمل دون إنترنت.
- الساعة المرجعية من الخادم مع رصد التراجع واستخدام الزمن الرتيب حيث
  يناسب؛ لا ندعي مقاومة مطلقة لجهاز معدل أو حاسوب خاضع للمهاجم.
- التخفيض تحت عدد الأجهزة النشطة يستلزم اختيار الأجهزة المتبقية وتحذيرًا
  واضحًا، لا حذف عشوائي. نسند سلوك الفوترة إلى قواعد قناة الشراء.

## 7. مراحل التنفيذ وشروط القبول

### المرحلة 0: تثبيت النطاق والعقود

المخرجات: إجابات القسم 3، جرد المزايا المنفذة، مصفوفة صلاحيات، مخططات
حالات الاشتراك والمقعد والجلسة، واختيار تقنية الخادم واستضافته بعد مقارنة
التكلفة والتشغيل والتوافق مع المتاجر. تقدير العمل يأتي بعد هذا الحسم.

القبول: لا غموض في بداية التجربة أو استهلاك المقعد أو نهاية الصلاحية.

### المرحلة 1: إغلاق الأمان المحلي والاستقرار

- تفعيل TLS مثبت الهوية افتراضيًا، دون رجوع صامت إلى النص الصريح.
- موافقة محلية صريحة للاقتران الأول، QR مؤقت، وإزالة الرمز الثابت من
  الإعداد التجاري؛ خطة ترحيل لا تحذف الاقترانات القائمة دون تنبيه.
- إغلاق حدود ردود Android والمهل والموارد ومراجعة التخمين والإغراق.
- فصل صلاحيات الماوس والكيبورد والطاقة، وتأكيد أوامر الطاقة ومسار الإلغاء.
- تثبيت السحب والتمرير والتصحيح والعربية وتغير الشبكة وملفات الحواسيب.

القبول: رفض شهادة مختلفة وهاتف غير مخول، لا تكرار لمدخلات غير مؤكدة،
واختبارات فعلية على Windows 10/11 وهواتف وشبكات متعددة دون تعديل يدوي
لمسارات كل عميل. لا نضمن تجاوز عزل شبكة يمنع الأجهزة من التواصل.

### المرحلة 2: تطوير الخادم المركزي الخاص بالمشروع

هذه مرحلة بناء Backend مستقل، وليست مجرد إضافة شاشة تسجيل دخول.
الخادم المركزي منفصل عن سيرفر التحكم المحلي الحالي على Windows.
يبدأ تصميمه في المرحلة 0، وتطويره هنا بعد تثبيت العقود؛ تكامل التراخيص
والدفع في المراحل التالية يبنى فوقه. لا يبدأ شراء استضافة أو نشر إنتاجي
إلا بعد اعتماد التكلفة والملكية وإدارة الأسرار.

#### 2A. البنية والبيئات

- اختيار إطار Backend وقاعدة بيانات علائقية ومزود بريد واستضافة مناسبة؛
  توثيق أسباب الاختيار وتكلفة التشغيل المتوقعة دون افتراض مزود محدد الآن.
- نطاق API وشهادة HTTPS، فصل التطوير والاختبار والإنتاج، وهجرات قاعدة
  بيانات قابلة للتدقيق، وخط بناء ونشر واختبار مع رجوع آمن.
- إدارة أسرار ومفاتيح توقيع خارج المستودع، أقل صلاحيات للخدمات والمشغلين،
  وحدود طلبات ومراقبة صحة الخدمة. لا منافذ تحكم بالحواسيب عبر الخادم.

#### 2B. نموذج البيانات وواجهات API

- تصميم المستخدم والحساب الرئيسي والعضوية والهاتف ومفتاحه العام والمقعد
  والدعوة والاشتراك والاستحقاق وإشعار الدفع وسياسة الإصدار وسجل التدقيق.
- عقود API مرقمة وموثقة للتسجيل والتوثيق والدخول والتجديد والخروج،
  إدارة الأجهزة والدعوات، طلب التفعيل والتصريح، والتحقق من إصدار التطبيق.
- قيود فريدة ومعاملات لمنع استهلاك المقعد مرتين، ومفاتيح تكرار آمن للعمليات
  الحساسة. فحص ملكية كل مورد لمنع الوصول بين الحسابات والمشتركين.
- عقود توقيع التصاريح والتحقق من المتاجر تصمم هنا، وتنفذ وتختبر بالكامل
  في مرحلتي التراخيص والدفع، لا تمنح استحقاقًا اعتمادًا على بيانات العميل.

#### 2C. وظائف الحساب والأمان

- التسجيل، توثيق البريد، الدخول والخروج، إعادة تعيين كلمة المرور وحذف الحساب.
- جلسات قصيرة ورموز تجديد مدوّرة وإبطال الجلسات، وحدود طلبات ومكافحة إساءة.
- تخزين كلمات المرور بتجزئة مناسبة أو استخدام مزود هوية موثوق؛ لا نظام
  تشفير كلمات مرور منزلي. عدم كشف وجود البريد في رسائل الاستعادة.
- بيانات منظمة للمستخدمين والعضويات والدعوات والهواتف والاشتراكات وأحداث
  الدفع والتصاريح، مع قيود فريدة ومعاملات وتدقيق محدود البيانات.
- فصل التطوير والتجربة والإنتاج، إدارة أسرار، نسخ احتياطي وتجربة استعادة.

#### 2D. التشغيل والإدارة

- لوحة إدارة محمية بصلاحيات ومصادقة متعددة العوامل للمشغلين: حالة الحساب
  والاستحقاق والتفعيل والدعوة، دون كلمات المرور أو مفاتيح المستخدم الخاصة.
- بريد التوثيق والاستعادة والدعوات مع حدود إرسال وإعادة محاولة آمنة،
  ومراقبة فشل التسليم دون تسجيل الرموز السرية.
- وظائف خلفية لإنهاء الدعوات والحجوزات، معالجة أحداث الدفع والتسوية،
  وسياسة حذف واحتفاظ بالبيانات. لا تنفذ وظائف الدفع قبل ربط المتجرين.
- مقاييس وأخطاء وتنبيهات منقحة، نسخ احتياطي مشفر واختبار استعادة،
  ودليل أعطال وتدوير مفاتيح وتحديثات أمنية وتقدير سعة وتكلفة.

المخرجات: مصدر Backend داخل المشروع، مخطط بيانات وهجرات، مواصفة API،
خدمة staging قابلة للاختبار بعد اعتماد نشرها، اختبارات آلية، ودليل تشغيل.
الخادم الإنتاجي يجهز لاحقًا قبل الاختبار المحدود، وليس قبل اكتمال الحماية.

القبول: انتهاء/إعادة استخدام رموز التوثيق، اختطاف الجلسات وتكرار الطلبات
والتفعيل المتزامن مختبرة؛ لا منح وصول لحساب غير موثق. يشترط أيضًا نجاح
اختبار فصل الحسابات واستعادة النسخ الاحتياطية وترقية المخطط ونشر إصدار
تجريبي دون تسريب أسرار، مع تحقق من حدود الموارد وتكلفة التشغيل.

### المرحلة 3: محرك التراخيص والتكامل المحلي

- إصدار تصاريح تجريبية موقعة والتحقق منها في Android وWindows.
- حالات تجربة/نشط/منتهٍ/ملغى/يتطلب تحققًا/يتطلب تحديثًا، منفصلة عن حالات
  الاتصال والاقتران. الإلغاء لا يعني دائمًا انتهاء الوصول فورًا.
- تنفيذ التحقق اليومي والسماح والتنبيهات والبصمة الاختيارية.
- تنفيذ الدعوات وإدارة الأجهزة والحجز والاستبدال والعزل بين الحسابات.
- إصدار API وبروتوكول واضح ورسائل أخطاء عملية دون أسرار في السجلات.

القبول: التصريح المزور أو المنتهي أو المنسوخ لهاتف آخر مرفوض، تعطل
التفعيل لا يبطل تصريحًا صالحًا، وانتهاء الصلاحية لا يحذف اقترانات المستخدم.

### المرحلة 4: نسخة iPhone

- اختيار التنفيذ بعد نموذج لإدخال النص والشبكة المحلية والماسح؛ لا إعادة
  كتابة Android تلقائيًا لمجرد مشاركة الواجهة.
- تنفيذ نفس عقود الحساب والترخيص والبروتوكول المحلي على iOS، مع Keychain
  ومفتاح جهاز محمي وFace ID/Touch ID اختياريين بحسب الجهاز.
- شرح أذونات الشبكة والكاميرا، معالجة دورة حياة التطبيق وقيود الخلفية،
  وتجربة فعلية على iPhone باستخدام أدوات بناء وتوقيع Apple المناسبة.

القبول: اقتران وكتابة عربية/إنجليزية وإعادة اتصال وترخيص على أجهزة فعلية.
لا وعد بعمل دائم بالخلفية يخالف قيود النظام.

### المرحلة 5: الدفع عبر المتجرين

- نموذج مبكر لمنتجات الباقة والمقاعد قبل الالتزام بتصميم تسعير نهائي.
- ربط شراء المتجر بالحساب الصحيح والتحقق الخادمي من أدلة الشراء.
- معالجة إشعارات التجديد والإلغاء والتعثر والاسترداد خارج ترتيب الوصول
  وبشكل متكرر آمن؛ مراجعة دورية عند فقد إشعار.
- استعادة المشتريات، منع ربط شراء واحد بمالكين دون سياسة نقل موثقة،
  وعدم إنشاء اشتراك مزدوج دون تحذير واضح عند الانتقال بين المنصتين.
- عرض السعر والعملة والتجديد ونهاية التجربة قبل التأكيد. تجربة الشهر
  لا تتحول إلى سحب مالي دون موافقة شراء صحيحة.

القبول: نجاح اختبارات sandbox في المتجرين، بما فيها الدفع المكرر والإلغاء
والاسترداد وشراء مقعد عند امتلاء الحد. الخادم يمنح الاستحقاق، لا واجهة الدفع.

### المرحلة 6: برنامج Windows القابل للتوزيع والدعم

- مثبت قابل للتحديث والإزالة، تشغيل تلقائي اختياري، وتوقيع إصدار مناسب.
- عدم مطالبة المستخدم بتعطيل الجدار الناري؛ أذونات شبكية محدودة ومعلنة.
- ترحيل الإعدادات والهويات، تراجع آمن عند فشل التحديث، وتوافق هاتف/حاسوب.
- موقع دعم وسياسة خصوصية وشروط واستخدام وإدارة حساب، دون قناة تحكم سحابية.
- تشخيص يرسله المستخدم بموافقته بعد تنقيح الأسرار والنصوص وعناوينه الحساسة.

القبول: تثبيت وترقية وإزالة على Windows نظيف، دون Python يدوي أو فقدان
هوية الحاسوب أو الاقترانات. المثبت ليس بديلًا عن اختبارات المنتج.

### المرحلة 7: اختبار شامل وإطلاق محدود

- مصفوفة Android/iOS/Windows، لغات واتجاهات واجهة وأجهزة وشبكات فعلية.
- محاكاة تأخر وتذبذب وفقد شبكة، إغلاق التطبيق وإعادة تشغيل الجهاز والسيرفر.
- قياس p50/p95 لزمن الأوامر والانتظار والاكتشاف والاستعادة على بيئة معلومة؛
  تحديد حدود قبول رقمية بعد خط أساس، لا ادعاءات سرعة دون قياس.
- اختبار تعطل خدمة التفعيل والبريد والدفع، تغيير الساعة، جهاز مفقود، دعوة
  ملغاة، تفعيلين متزامنين على المقعد الوحيد، نهاية تجربة واسترداد ونسخة إلزامية قديمة.
- مراجعة أمن وخصوصية، اختبار استعادة قاعدة البيانات وتدوير المفاتيح.
- إتاحة حساب/وضع اختبار وتعليمات محلية مناسبة لمراجعي المتاجر دون تعطيل
  حماية مستخدمي الإنتاج أو إنشاء باب خلفي.

القبول: لا عيوب حرجة أو فقدان بيانات معروف، نجاح مصفوفة السيناريوهات،
وضوح الموافقات والأسعار والحذف، وخطة دعم واستجابة للحوادث قبل البيع العام.

### المرحلة 8: النشر والتشغيل

- حسابات المطورين وملكية الاسم والمعرفات والشهادات ومواد المتاجر وإفصاحات
  البيانات والأذونات جاهزة. قبول المتجر ليس مضمونًا بمجرد اكتمال البناء.
- توزيع اختباري عبر قنوات المتجرين ثم إطلاق تدريجي قابل للإيقاف.
- متابعة أعطال وتفعيل ودفع بحد أدنى من البيانات، دون مراقبة الكتابة.
- دليل تشغيلي للتعطل والإلغاء والاسترداد ودعم العملاء والتحديث الأمني.
